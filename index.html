The problem

When an AI agent fans out to 3 paid data sources via x402 or a402, sources settle independently over HTTP. If source #3 over-bills or times out, sources #1 and #2 have already cashed your USDC. The agent's budget is half-spent on a half-answer. No atomicity, no rollback.

What Quikt does

Quikt binds payments to N sources into a single Sui Programmable Transaction Block. The PTB calls pay_and_record once per source. Either all N payments + cryptographic blob commitments land in one tx, or the whole bundle reverts. Atomicity is enforced by Sui's type system — a hot-potato ResearchReceipt struct cannot be dropped without being consumed by settle_research_call.

How the Move package works

public struct ResearchReceipt {           // no abilities — hot potato
    session_id: ID,
    payee: address,
    amount: u64,
    blob_hash: vector<u8>,
    nonce: u64,
}

public fun pay_and_record<T>(
    session: &mut ResearchSession<T>,
    ...
): ResearchReceipt { /* mints the hot potato */ }

public fun settle_research_call<T>(
    session: &mut ResearchSession<T>,
    receipt: ResearchReceipt,   // MUST consume — no drop ability
) { /* records to dynamic-field registry */ }

Move's ability system makes "forgot to settle" a compile-time error, not a runtime exploit. The whole PTB reverts if any receipt isn't consumed.
